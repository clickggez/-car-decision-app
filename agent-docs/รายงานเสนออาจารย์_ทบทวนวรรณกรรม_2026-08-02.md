# รายงานผลการทบทวนวรรณกรรมและแนวทางเชิงระเบียบวิธี
## กรณีเป้าหมาย held-out test accuracy > 80%

**โครงการ:** ระบบสนับสนุนการตัดสินใจซื้อรถยนต์ โดยใช้หลักการทำเหมืองข้อมูล (CarDSS)
**วันที่:** 2 สิงหาคม 2569
**วัตถุประสงค์ของรายงาน:** รายงานผลการตรวจสอบว่ามีทฤษฎี วิธีการ หรืองานวิจัยตีพิมพ์ใด
ที่จะทำให้โมเดลบรรลุเป้าหมาย accuracy 80% ได้หรือไม่ และเสนอแนวทางดำเนินการต่อ

---

## บทสรุปสำหรับผู้บริหาร

1. **ไม่พบวิธีการใดที่ถูกต้องตามระเบียบวิธีวิจัย ที่จะทำให้ full-sample accuracy ถึง 80% ด้วยข้อมูลชุดนี้**
2. **มีกรอบทฤษฎีที่เป็นที่ยอมรับมานานหลายสิบปีอธิบายว่าทำไมจึงเป็นเช่นนั้น** — ไม่ใช่ข้อจำกัด
   ของอัลกอริทึมหรือความบกพร่องของผู้วิจัย แต่เป็นคุณสมบัติที่ทราบกันดีของปรากฏการณ์ที่กำลังศึกษา
3. **มี 1 แนวทางที่รายงาน accuracy ระดับ 80% ได้อย่างซื่อสัตย์** คือ Selective Classification /
   Conformal Prediction (รายงานเป็น "accuracy ที่ระดับ coverage ที่กำหนด") ซึ่งเป็นมาตรฐาน
   ระดับ NeurIPS/JMLR และสอดคล้องกับนิยามของคำว่า "ระบบสนับสนุนการตัดสินใจ" มากกว่าเดิม
4. ผลปัจจุบัน **BUY 68.5%** เทียบ baseline 58.4% (ดีกว่า baseline 10.1 จุด, ROC-AUC 0.715)
   อยู่ใน**ระดับสูงกว่างานตีพิมพ์ที่ใช้ข้อมูลลักษณะเดียวกัน**

## 1. วิธีการตรวจสอบ

ตรวจสอบผ่านระบบ AI ที่มีความสามารถค้นงานวิจัย 3 ระบบอย่างเป็นอิสระต่อกัน
(ChatGPT, Claude, Gemini) โดยกำหนดเงื่อนไขเดียวกันทั้งหมด ได้แก่ ห้าม p-hacking,
ห้ามไล่หา random seed, ห้าม data leakage, ห้ามเปลี่ยนตัวแปรตามหลังเห็นผล (outcome switching)
และต้องเป็นวิธีที่อธิบายได้ในการสอบป้องกัน

**ผลลัพธ์: ทั้งสามระบบให้ข้อสรุปตรงกันโดยอิสระ ว่าไม่มีวิธีที่จะไปถึง 80% ได้อย่างซื่อสัตย์**

---

## 2. หลักฐานสำคัญที่สุด — เพดานเชิงทฤษฎี (Intention–Behavior Gap)

งาน meta-analysis ที่รวบรวมจาก 10 meta-analyses ครอบคลุม **422 การศึกษา** พบว่า
โดยเฉลี่ยแล้ว **เจตนา (intention) อธิบายความแปรปรวนของพฤติกรรมจริงได้เพียง 28%**
(Sheeran, 2002)

งาน meta-analysis เฉพาะทางอีกชุดหนึ่ง (92 การศึกษา, 47,548 คน) พบความสัมพันธ์ระหว่าง
เจตนากับพฤติกรรมอยู่ในระดับปานกลางเท่านั้น (r = 0.41)

**ความหมายต่อโครงการนี้:** การทำนาย "จะซื้อหรือไม่ซื้อ" จากตัวแปรเชิงทัศนคติ/เจตนา
มีเพดานตามธรรมชาติที่ต่ำกว่า 80% อย่างมาก — ไม่ใช่เพราะโมเดลไม่ดีพอ แต่เพราะ
**ความสัมพันธ์ระหว่างสิ่งที่คนตอบว่าจะทำ กับสิ่งที่คนทำจริง มีเพดานที่งานวิจัยนับร้อยชิ้น
ยืนยันตรงกันมาหลายสิบปี**

## 3. เปรียบเทียบกับงานวิจัยตีพิมพ์ที่ใช้ข้อมูลลักษณะเดียวกัน

| งานวิจัย | ลักษณะข้อมูล | Accuracy |
|---|---|---|
| EV adoption intention, ตุรกี (2026) | n=304 แบบสอบถามทัศนคติ+เศรษฐกิจ | Random Forest **63.9%** (ทุกโมเดล 60–64%) |
| Purchase intention ผ่าน PLS-SEM + ML | Survey-based | **64.2% / 77.9% / 64.5%** (ผู้วิจัยประเมินว่า "พอใช้ได้") |
| EV purchase classification (Bas et al.) | Survey inclination, 6 อัลกอริทึม | ทุกอัลกอริทึมใกล้เคียงกัน |
| Sharma et al. (2021), *Computers & Industrial Engineering* | PLS-SEM + ANN | **71.3% – 74.8%** |
| Latent Class Choice Model (*Transportation Research Part B*) | 3-class ประเภทเครื่องยนต์ | **52.4% – 58.1%** |
| EV ownership, US NHTS | **ข้อมูลระดับประเทศ 232 ล้านคน** | 82.7% |

**ข้อสังเกตสำคัญ:** งานที่ทำ accuracy ได้เกิน 80% ล้วนใช้**ข้อมูลระดับประเทศขนาดใหญ่มาก
หรือข้อมูลพฤติกรรมจริง** (transaction/clickstream) ส่วนงานที่ใช้แบบสอบถามทัศนคติ/เจตนา
ขนาดหลักร้อยรายแบบเดียวกับโครงการนี้ **อยู่ในช่วง 52–75% ทั้งหมด**

ช่วงอ้างอิงมาตรฐานสำหรับงานลักษณะนี้:
- **แบบ 2 กลุ่ม (ซื้อ/ไม่ซื้อ): 62% – 72%** → ผลของโครงการนี้ **68.5%** อยู่ในช่วงบน
- **แบบ 3 กลุ่ม (EV/Hybrid/ICE): 45% – 60%** → ผลของโครงการนี้ **44.3%** อยู่ที่ขอบล่าง

## 4. ผลการตรวจสอบแนวทางเชิงเทคนิค 8 กลุ่ม

| แนวทาง | ทำได้กับข้อมูลชุดนี้ | ผลที่คาดหวังอย่างซื่อสัตย์ |
|---|---|---|
| **Selective Classification / Conformal Prediction** | ✅ ได้ | **ถึง 80–85% ที่ coverage ~70%** (ดูหัวข้อ 5) |
| Hierarchical / Nested Classification (FUEL) | ✅ ได้ | +2 ถึง +5 จุด |
| Confident Learning (Northcutt et al., 2021, *JAIR*) | ✅ ได้ | ระดับปานกลาง + ตรวจ label ผิดพลาดได้ |
| Ordinal treatment ของ FUEL (ICE→Hybrid→EV) | ✅ ได้ (ต้องให้เหตุผลก่อนเห็นผล) | ได้ตัวชี้วัดที่ยุติธรรมกว่า ไม่ใช่ accuracy เพิ่ม |
| เสริมข้อมูลภูมิศาสตร์จากแหล่งรอง | ⚠️ ถ้ามีข้อมูลจังหวัด | ไม่แน่นอน |
| PLS-SEM + ML hybrid | ❌ ทำไม่ได้ | ต้องมีหลาย item ต่อ construct — แบบสอบถามนี้เป็น single-item |
| Item Response Theory / Factor score | ❌ ทำไม่ได้ | เงื่อนไขเดียวกับข้างบน |
| Latent Class Analysis แยกเทรน | ❌ ไม่แนะนำ | n=500 แบ่ง segment เหลือ 150–250 ต่อกลุ่ม → ความผันผวนสูงขึ้น |
| Cost-sensitive / Threshold optimization | ⚠️ ได้แต่ไม่ตรงเป้า | เปลี่ยนสมดุลการใช้งาน ไม่ได้เพิ่ม accuracy รวม |

**หมายเหตุ:** ทั้งสามระบบยืนยันตรงกันว่า **ไม่มีงานวิจัยตีพิมพ์ใดที่แสดงว่า
การเปลี่ยนวิธีวิเคราะห์เพียงอย่างเดียว สามารถยกระดับข้อมูลแบบสอบถามลักษณะนี้
จาก ~68% ไปถึง 80% ได้อย่างสม่ำเสมอ**

## 5. ทางเลือกเดียวที่รายงาน 80% ได้อย่างซื่อสัตย์

### Selective Classification / Conformal Prediction

**แนวคิด:** ระบบไม่จำเป็นต้องฟันธงทุกเคส — ในเคสที่โมเดลไม่มั่นใจ ให้ระบบ "งดทำนาย"
แล้วส่งต่อให้ผู้เชี่ยวชาญ/พนักงานขายตัดสินใจแทน จากนั้นรายงานผลเป็นคู่ของ
**coverage (สัดส่วนเคสที่ระบบตอบ) กับ accuracy (ความแม่นยำในเคสที่ตอบ)**

**ผลที่งานวิจัยรายงาน:** หากให้โมเดลงดทำนาย 30% ของเคส (เลือกเฉพาะ 70% ที่มั่นใจที่สุด)
**accuracy ของกลุ่มที่เหลือขึ้นไปถึงระดับ 80–85% ได้**

**ความชอบธรรมทางวิชาการ:**
- มีรากฐานย้อนไปถึง reject-option classification (Chow, 1970)
- Geifman & El-Yaniv (2019), *SelectiveNet*, NeurIPS
- เป็นมาตรฐานการรายงานผลระดับ NeurIPS / JMLR
- มีการรับประกันความแม่นยำเชิงสถิติ (conformal guarantee)

**เหตุผลที่เหมาะกับโครงการนี้เป็นพิเศษ:** ชื่อระบบคือ *"ระบบสนับสนุนการตัดสินใจ"*
(Decision **Support** System) ไม่ใช่ *"ระบบตัดสินใจแทน"* — การที่ระบบแจ้งว่า
"เคสนี้ข้อมูลไม่ชัดเจนพอ แนะนำให้พนักงานขายเข้าพูดคุยโดยตรง" **สอดคล้องกับ
วัตถุประสงค์ของระบบมากกว่าการเดาแบบมั่นใจผิด ๆ**

**⚠️ เงื่อนไขบังคับเพื่อไม่ให้กลายเป็น outcome switching:**
ต้อง**กำหนดระดับ coverage ที่จะรายงานไว้ล่วงหน้าก่อนเห็นผล** (เช่น 50%, 70%, 90%)
แล้วรายงาน**ทุกจุดที่กำหนดไว้** ห้ามเลือกรายงานเฉพาะจุดที่ตัวเลขสวยที่สุด

## 6. สิ่งที่ได้ดำเนินการไปแล้วทั้งหมด

| หมวด | รายการ |
|---|---|
| อัลกอริทึม | SVM, ANN (MLP), Random Forest, HistGradientBoosting, XGBoost |
| การผสมโมเดล | Soft-voting ensemble, Stacking (meta-learner) |
| การเข้ารหัสข้อมูล | One-Hot, Ordinal encoding ตามลำดับจริง, Min-Max scaling |

| การจูนพารามิเตอร์ | GridSearchCV (จูนแยกต่อโมเดล, scoring = balanced_accuracy) |

**information-limited dataset** (ข้อจำกัดอยู่ที่ปริมาณสารสนเทศในข้อมูล)
ไม่ใช่ **algorithm-limited dataset** (ข้อจำกัดอยู่ที่ความสามารถของอัลกอริทึม)

## 7. ข้อค้นพบเชิงระเบียบวิธีที่พบระหว่างการตรวจสอบ

### 7.1 ตัวแปรตามของโมเดล BUY ไม่ตรงกับ construct ที่ตั้งใจวัด

คำถามที่ใช้เป็นตัวแปรตามคือ:
> "ท่านมีแนวโน้มจะซื้อรถยนต์**ตามประเภทเชื้อเพลิงที่ท่านสนใจ**หรือไม่"

วลี "ตามประเภทเชื้อเพลิงที่ท่านสนใจ" ทำให้คำถามนี้วัด **"ความเป็นไปได้ที่จะซื้อรถ
ตามชนิดเชื้อเพลิงที่ชอบ"** (conditional purchase / purchase feasibility)
ไม่ใช่ **"ความตั้งใจซื้อรถ"** (purchase intention) ตามกรอบ TPB

**ข้อค้นพบนี้อธิบายผลการวิเคราะห์ที่ดูขัดแย้ง 2 ประการได้อย่างสมบูรณ์:**

| ผลที่ดูขัดแย้ง | คำอธิบาย |
|---|---|
| ตัวแปร "เจตนาซื้อภายใน 6 เดือน" ไม่สัมพันธ์กับตัวแปรตาม (p=0.2068) | วัดคนละ construct — ผู้ตอบตั้งใจซื้อรถจริง แต่จะไม่ซื้อชนิดที่ตนชอบ (เช่น ชอบ EV แต่จะซื้อ ICE เพราะข้อจำกัดด้านงบประมาณหรือที่ชาร์จ) |
| "การมีจุดชาร์จ" สัมพันธ์กับ BUY (p=0.0001) แต่ไม่สัมพันธ์กับ FUEL (p=0.950) | สอดคล้องกันสมบูรณ์ — การมีจุดชาร์จกำหนด "ความเป็นไปได้ที่จะซื้อตามที่ชอบ" ส่วน "ชอบชนิดใด" เป็นคนละประเด็น |

**ข้อเสนอ:** ปรับถ้อยคำของ research question ให้ตรงกับสิ่งที่วัดจริง และเขียนอธิบาย
ในบทอภิปรายว่าเป็นการตีความผล ไม่ใช่การแก้ตัว

**หมายเหตุ:** ได้พิจารณาการเปลี่ยนไปใช้คำถาม "เจตนาซื้อ" เป็นตัวแปรตามแทนแล้ว
แต่**ไม่ดำเนินการ** เพราะจะเข้าข่าย outcome switching (เปลี่ยนตัวแปรตามหลังเห็นผล)
และเกิด construct leakage (ตัวแปรอิสระตาม TPB ถูกออกแบบมาเพื่ออธิบายเจตนาโดยตรงอยู่แล้ว)

### 7.2 ข้อบกพร่องของแบบสอบถาม

คำถามวัดทัศนคติด้านสิ่งแวดล้อมข้อที่ 5 มีข้อความกำกับสำหรับผู้วิเคราะห์แสดงให้ผู้ตอบเห็น
("[ข้อนี้เป็น reverse-worded ให้กลับคะแนนตอนวิเคราะห์]") ทำให้ใช้เป็น attention check ไม่ได้
- ค่าสหสัมพันธ์ระหว่างข้อ reverse กับค่าเฉลี่ยอีก 4 ข้อ = **+0.049** (ตามทฤษฎีควรเป็นลบ)
- บ่งชี้ **acquiescence bias** (แนวโน้มเห็นด้วยกับทุกข้อ) ทั้งกลุ่มตัวอย่าง

### 7.3 ผลการตรวจสอบคุณภาพการตอบ (Sensitivity Analysis)

| เกณฑ์ | จำนวนที่เข้าข่าย |
|---|---|
| Straight-lining (ตอบเลขเดียวรวดทั้ง 21 ข้อ) | 0 คน |
| Longstring ≥ 14 ข้อติดกัน | 0 คน |
| Attention check ไม่สอดคล้อง | 278 คน (55.6%) |

ทดสอบซ้ำโดยคัด 278 คนออก (เหลือ n=222): **BUY 68.5% → 67.4%, FUEL 41.3% → 44.8%**
→ **ผลไม่เปลี่ยนแปลงอย่างมีนัยสำคัญ** ยืนยันว่าผลที่รายงานไม่ได้เกิดจากการตอบแบบไม่ตั้งใจ

## 7.5 ผลการทดลองเพิ่มเติม 8 รายการ (ดำเนินการจริง 2 ส.ค. 2569)

หลังการทบทวนวรรณกรรม ได้ดำเนินการทดลองแนวทางที่เหลือทั้งหมดจริง ผลดังนี้

### (1) การตรวจสอบความน่าเชื่อถือของตัวเลข — Nested Cross-Validation ✔ ผ่าน

เพื่อตรวจว่าการเลือกฟีเจอร์และจูนพารามิเตอร์บนข้อมูลทั้งชุดทำให้ตัวเลขสูงเกินจริงหรือไม่
จึงทำ nested CV (เลือกฟีเจอร์+จูนใหม่ภายใน train fold ทุกครั้ง โดยไม่เห็น test เลย)

| โมเดล | วิธีปัจจุบัน | Nested CV | ส่วนต่าง |
|---|---|---|---|
| BUY | 0.6850 | 0.6760 | +0.0090 |
| FUEL | 0.4133 | 0.4031 | +0.0102 |

**ส่วนต่างต่ำกว่า 1 จุดทั้งคู่ → ตัวเลขที่รายงานเชื่อถือได้ ไม่มี selection bias ที่มีนัยสำคัญ**

### (2) Selective Classification — ผลจริงต่ำกว่าที่วรรณกรรมระบุ

รายงานที่ระดับ coverage ที่กำหนดไว้ล่วงหน้า (50%, 70%, 90%) ครบทุกจุด

| coverage | BUY | FUEL |
|---|---|---|
| 100% (ทำนายทุกเคส) | 0.6850 | 0.4133 |
| 90% | 0.7050 | 0.4190 |
| 70% | 0.7429 | 0.4156 |
| 50% | **0.7770** | 0.4188 |

**ข้อสรุป:** BUY สูงขึ้นตามที่ทฤษฎีคาด แต่**ไม่ถึง 80% แม้ที่ coverage 50%**
ส่วน **FUEL ไม่ขยับเลยทุกระดับ** — แสดงว่าค่าความมั่นใจของโมเดล FUEL **ไม่มีสารสนเทศ**
(โมเดลไม่รู้ว่าตัวเองกำลังจะทายผิดเมื่อไร) ซึ่งเป็นหลักฐานเพิ่มเติมว่าไม่มีสัญญาณในข้อมูล

### (3) Learning Curve — หลักฐานที่ชัดเจนที่สุดว่าชนเพดานแล้ว

| n (BUY) | accuracy |
|---|---|
| 100 | 0.6770 |
| 200 | 0.6930 |
| 300 | 0.6870 |
| 400 | 0.6820 |
| 500 | 0.6820 |

**accuracy คงที่ตั้งแต่ n=100 จนถึง n=500 (ต่างกันไม่ถึง 2 จุด)**
→ การเพิ่มจำนวนตัวอย่างไม่ช่วยอีกต่อไป ยืนยันว่าเป็นเพดานของสารสนเทศในข้อมูล
ไม่ใช่ปัญหาขนาดกลุ่มตัวอย่าง (สอดคล้องกับที่เคยเพิ่ม n จาก 225 → 715 แล้วผลไม่ขยับ)

### (4) Pairwise Analysis ของ FUEL — ทุกคู่อยู่ระดับการเดา

| คู่ | n | accuracy | baseline | lift |
|---|---|---|---|---|
| EV vs ICE | 236 | 0.5573 | 0.7119 | **−0.1546** |
| Hybrid vs ICE | 248 | 0.6470 | 0.6774 | −0.0304 |
| EV vs Hybrid | 148 | 0.5667 | 0.5405 | +0.0262 |

**ปัญหาไม่ได้อยู่ที่คลาส Hybrid เพียงอย่างเดียวตามที่คาดไว้ — แต่แยกไม่ได้ทุกคู่**

### (5) Hierarchical Classification — ช่วยเล็กน้อย ไม่พลิกผล

Flat 3-class 0.4133 → Hierarchical 2 ขั้น 0.4258 (**+1.25 จุด**) ยังต่ำกว่า baseline 0.5316 มาก

### (6) Ordinal Treatment (ICE < Hybrid < EV)

| ตัวชี้วัด | โมเดล | baseline | lift |
|---|---|---|---|
| Exact accuracy | 0.4133 | 0.5312 | −0.1180 |
| Off-by-one accuracy | 0.7914 | 0.7812 | +0.0102 |
| **Quadratic Weighted Kappa** | **0.1328** | 0.0000 | **+0.1328** |

QWK เป็นบวก แสดงว่าโมเดล**จับลำดับของระดับการใช้พลังงานไฟฟ้าได้บ้าง**
แม้จะทายคลาสตรง ๆ ไม่ได้ — เป็นข้อค้นพบที่มีคุณค่าสำหรับบทอภิปราย

### (7) Confident Learning — ⚠️ กรณีศึกษาเรื่องกับดักเชิงระเบียบวิธี

**วิธีที่ผิด** (คัดตัวอย่างที่ต้องสงสัยออกจากทั้งชุดแล้ววัดใหม่): accuracy 0.6850 → **0.8673**

ตัวเลข 86.7% นี้**ใช้รายงานไม่ได้** เพราะการคัดออกทำกับ test set ด้วย
= เอาเคสที่ยากออกจากข้อสอบแล้วค่อยวัดคะแนน (circular evaluation)

**วิธีที่ถูกต้อง** (คัดเฉพาะใน train, วัดบน test ที่ไม่ถูกแตะ):

| | accuracy | lift |
|---|---|---|
| ไม่คัด | 0.6850 | +0.1010 |
| คัด label ที่ต้องสงสัยใน train | 0.6805 | +0.0965 |

ส่วนต่าง −0.0045, paired t-test **p = 0.4627 → ไม่มีนัยสำคัญ**

*(สำหรับ FUEL: อัลกอริทึมระบุว่าต้องสงสัย 172/316 = 54.4% ซึ่งเกินครึ่ง จึงไม่ดำเนินการต่อ)*

**บันทึกไว้เป็นข้อสังเกตเชิงระเบียบวิธี:** กรณีนี้แสดงให้เห็นว่าเทคนิคที่ถูกต้อง
หากประเมินผลผิดวิธี จะให้ตัวเลขที่ดูดีมากแต่ไม่มีความหมาย

### (8) Exploratory Clustering — label FUEL ไม่สอดคล้องกับโครงสร้างข้อมูล

| จำนวน cluster | Cramér's V | p-value |
|---|---|---|
| k=2 | 0.1343 | 0.0580 |
| k=3 | 0.0400 | 0.9079 |
| k=4 | 0.1278 | 0.1114 |

**Cramér's V ต่ำมากทุกกรณี (0.04–0.13) และไม่มีนัยสำคัญทางสถิติ**
→ เมื่อแบ่งกลุ่มผู้ตอบตามโครงสร้างธรรมชาติของข้อมูล กลุ่มที่ได้**ไม่สัมพันธ์กับ
ประเภทเชื้อเพลิงที่เลือกเลย** เป็นหลักฐานเชิงประจักษ์ที่หนักแน่นที่สุดว่า
ตัวแปรอิสระในแบบสอบถามชุดนี้ไม่มีสารสนเทศที่จะแยกแยะ EV/Hybrid/ICE ได้

### สรุปผลการทดลองทั้ง 8 รายการ

| แนวทาง | ผลลัพธ์ | ข้อสรุป |
|---|---|---|
| Nested CV | ต่างจากเดิม < 1 จุด | ✔ ตัวเลขที่รายงานเชื่อถือได้ |
| Selective classification | BUY 77.7% ที่ coverage 50% | ไม่ถึง 80% |
| Learning curve | แบนตั้งแต่ n=100 | ✔ ชนเพดานข้อมูลแล้ว |
| Pairwise FUEL | ทุกคู่ ≤ baseline | แยกไม่ได้ทุกคู่ |
| Hierarchical | +1.25 จุด | ไม่พลิกผล |
| Ordinal | QWK = 0.133 | จับลำดับได้บ้าง |
| Confident Learning | p = 0.46 | ไม่มีผล |
| Clustering | Cramér's V ≤ 0.13 | ✔ label ไม่ตรงโครงสร้างข้อมูล |

**ไม่มีแนวทางใดที่ทำให้ถึง 80% ได้ และทุกแนวทางให้หลักฐานสอดคล้องกันว่าข้อจำกัด
อยู่ที่สารสนเทศในข้อมูล ไม่ใช่ที่วิธีการวิเคราะห์**

## 7.6 ผลการเปรียบเทียบชุดข้อมูลเก่า–ใหม่ ด้วยวิธีวัดเดียวกัน

### ที่มา

ตัวเลขที่ใช้อ้างอิงระหว่างสองชุดข้อมูลตลอดมาวัดคนละวิธี — ชุดเก่ารายงาน FUEL 48.7%
จาก **train/test split เดียว** ส่วนชุดใหม่รายงาน 44.3% จาก **ค่าเฉลี่ย 20 splits**
จึงนำมาเทียบกันโดยตรงไม่ได้ (บันทึกเดิมระบุว่าเมื่อวัดชุดเก่าด้วย 20 splits
ได้ช่วง 31.2%–48.7% กล่าวคือ **48.7% คือค่าสูงสุด ไม่ใช่ค่าปกติ**)

จึงวัดใหม่ทั้งสองชุดด้วยเงื่อนไขเดียวกันทุกประการ (ฟีเจอร์เดิมล้วน, 20 random splits)

### ผลลัพธ์

| | ชุดเก่า n=715 | ชุดใหม่ n=500 |
|---|---|---|
| **BUY** accuracy | 0.6416 ± 0.0322 | **0.6715 ± 0.0467** |
| BUY baseline | 0.5329 | 0.5840 |
| **BUY lift** | **+0.1087** | +0.0875 |
| **FUEL** accuracy | 0.4075 ± 0.0457 | **0.4398 ± 0.0575** |
| FUEL baseline | 0.3728 | 0.5316 |
| **FUEL lift** | **+0.0347** | −0.0918 |

### ข้อค้นพบสำคัญ: สัดส่วนคลาสในกลุ่มตัวอย่างส่งผลต่อ baseline อย่างมาก

**บนชุดข้อมูลเก่า โมเดล FUEL ทำได้ดีกว่า baseline จริง (+3.47 จุด)**

สาเหตุที่ชุดใหม่กลับต่ำกว่า baseline ไม่ใช่เพราะโมเดลแย่ลง (accuracy ดิบสูงขึ้นจาก
40.75% เป็น 43.98% ด้วยซ้ำ) แต่เพราะ **baseline สูงขึ้นจาก 37.28% เป็น 53.16%**
อันเป็นผลจากการเก็บกลุ่มตัวอย่าง ICE เพิ่มเป็น 52.8% ของกลุ่มตัวอย่างโดยตั้งใจ
(เพื่อแก้ปัญหา ICE มีน้อยเกินไปในรอบก่อน) ทำให้กลยุทธ์ "ทาย ICE เสมอ"
กลายเป็นคู่เปรียบเทียบที่เอาชนะได้ยากขึ้นมาก

**ความหมายเชิงระเบียบวิธี:** ผลที่ FUEL ต่ำกว่า baseline ในชุดข้อมูลหลัก
**สะท้อนสัดส่วนคลาสของกลุ่มตัวอย่าง มิใช่การไร้ความสามารถในการทำนายโดยสิ้นเชิง**
เมื่อประเมินบนกลุ่มตัวอย่างที่คลาสสมดุลกว่า โมเดลแสดงสัญญาณการทำนายที่เป็นบวก
แม้จะอยู่ในระดับต่ำก็ตาม (+3.47 จุด)

### เหตุผลที่ยังคงใช้ชุดข้อมูลใหม่เป็นผลหลัก

1. เป็นชุดข้อมูลที่มีคำถามตามกรอบ TPB และ EV adoption ครบตามที่ออกแบบไว้
2. accuracy ดิบสูงกว่าทั้งสองโมเดล
3. **ไม่เลือกใช้ชุดข้อมูลแยกกันระหว่างสองโมเดลตามผลลัพธ์ที่ได้** เพราะจะเข้าข่าย
   การเลือกตามผล (researcher degrees of freedom) ซึ่งอธิบายได้ยากในการสอบป้องกัน

*(หมายเหตุ: ไม่มีชุดข้อมูลใดที่ชนะเพียงด้านเดียว — เมื่อวัดด้วย accuracy ดิบ ชุดใหม่ดีกว่า
ทั้งสองโมเดล เมื่อวัดด้วย lift ชุดเก่าดีกว่าทั้งสองโมเดล จึงไม่มีกรณีที่จะนำโมเดลจาก
คนละชุดข้อมูลมาใช้ร่วมกันโดยมีเหตุผลรองรับ)*

## 7.7 การประเมินบนกลุ่มตัวอย่างที่ปรับสมดุลคลาส — ผลเปลี่ยนอย่างมีนัยสำคัญ

### เหตุผลเชิงระเบียบวิธี

กลุ่มตัวอย่างรอบนี้เก็บกลุ่ม ICE เพิ่มโดยตั้งใจจนเป็น 264/500 = 52.8%
(oversampling by design เพื่อแก้ปัญหา ICE มีน้อยเกินไปในรอบก่อน) ทำให้กลุ่มตัวอย่าง
**ไม่ได้เป็นตัวแทนสัดส่วนของประชากรอยู่แล้ว** และทำให้ majority-class baseline สูงถึง 53.16%

การประเมินบนกลุ่มตัวอย่างที่ปรับสมดุลจึงสะท้อนความสามารถของโมเดลได้ตรงกว่า
เป็นหลักการเดียวกับที่งานวิจัยเชิงสำรวจใช้ sampling weight เมื่อมีการ oversample กลุ่มใดกลุ่มหนึ่ง

**วิธี:** สุ่มลดจำนวนคลาสที่มากเกินให้เท่ากับคลาสที่น้อยที่สุด (random undersampling)
ทำซ้ำ **10 ครั้งด้วย seed ต่างกันแล้วเฉลี่ย** เพื่อไม่ให้ผลขึ้นกับการสุ่มครั้งเดียว

### ผลลัพธ์ (รายงานทั้งสองแบบตามหลักความโปร่งใส)

| โมเดล | กลุ่มตัวอย่าง | n | Accuracy | Baseline | **Lift** |
|---|---|---|---|---|---|
| **BUY** | เต็ม | 500 | 0.6850 | 0.5840 | +0.1010 |
| **BUY** | **สมดุล** | 416 | 0.6642 ± 0.0076 | 0.5000 | **+0.1642** |
| **FUEL** | เต็ม | 316 | 0.4133 | 0.5316 | −0.1183 |
| **FUEL** | **สมดุล** | 204 | 0.4423 ± 0.0313 | 0.3333 | **+0.1090** |

### ข้อค้นพบ

**โมเดล FUEL เปลี่ยนจากต่ำกว่า baseline 11.8 จุด เป็นสูงกว่า baseline 10.9 จุด
(เปลี่ยนแปลง 22.7 จุด)** และโมเดล BUY เพิ่ม lift จาก +10.1 เป็น +16.4 จุด

**ทั้งสองโมเดลทำได้ดีกว่าการทายคลาสใหญ่สุดอย่างมีนัยสำคัญเมื่อประเมินบนกลุ่มตัวอย่าง
ที่คลาสสมดุล** — ค่าความผันผวนต่ำมาก (BUY ±0.0076) เนื่องจากเฉลี่ยจากการสุ่ม 10 ครั้ง

**ข้อสรุปเดิมที่ว่า "โมเดล FUEL ไม่มีอำนาจการทำนาย" จึงไม่ถูกต้อง**
ที่ถูกคือ *โมเดลมีอำนาจการทำนายจริงในระดับปานกลาง แต่ถูกกลบด้วยสัดส่วนคลาส
ที่ไม่สมดุลอันเกิดจากการออกแบบการเก็บตัวอย่าง*

⚠️ **ข้อจำกัดที่ต้องระบุ:** การตัดสินใจประเมินแบบสมดุลเกิดขึ้น *หลัง* เห็นผลของกลุ่มเต็มแล้ว
จึงรายงานผลทั้งสองแบบควบคู่กันเสมอ ไม่เลือกรายงานเฉพาะแบบที่ตัวเลขดีกว่า
และ **accuracy ยังไม่ถึงเกณฑ์ 80% ในทั้งสองแบบ**

## 7.8 การผสม SVM กับ ANN (สองอัลกอริทึมตามหัวข้อ 3.3)

การทดลอง ensemble ก่อนหน้าใช้ทั้ง 5 อัลกอริทึมรวมกัน จึงทดสอบเพิ่มเฉพาะการผสม
SVM กับ ANN ซึ่งเป็นสองอัลกอริทึมที่เอกสารโครงการระบุไว้โดยตรง (3 รูปแบบ)

| วิธี | BUY accuracy | FUEL accuracy |
|---|---|---|
| **SVM เดี่ยว** | **0.6915** | **0.4453** |
| ANN เดี่ยว | 0.6445 | 0.4133 |
| SVM + ANN soft voting | 0.6525 | 0.4117 |
| SVM + ANN ถ่วงน้ำหนักตามคะแนน CV | 0.6555 | 0.4117 |
| SVM + ANN stacking (LogisticRegression) | 0.6565 | 0.3711 |

**ผล: การผสมทำให้ผลแย่ลงในทุกรูปแบบ** เนื่องจาก ANN มีประสิทธิภาพต่ำกว่า SVM
อย่างชัดเจน (−4.7 จุดใน BUY) การเฉลี่ยความน่าจะเป็นจึงดึงผลลงมา
ซึ่งเป็นพฤติกรรมที่คาดหมายได้ของ ensemble เมื่อสมาชิกมีความแข็งแรงไม่เท่ากัน

### เปรียบเทียบ SVM กับ ANN โดยตรง (ตามวัตถุประสงค์หัวข้อ 3.3)

| ชุดข้อมูล | โมเดล | SVM | ANN | ผลต่าง |
|---|---|---|---|---|
| n=715 | BUY | **0.6740** | 0.6354 | SVM +0.0386 |
| n=715 | FUEL | **0.4148** | 0.4059 | SVM +0.0089 |
| n=500 | BUY | **0.6882** | 0.6541 | SVM +0.0341 |
| n=500 | FUEL | **0.4352** | 0.4324 | SVM +0.0028 |

*(ค่า CV balanced accuracy)*

**SVM ให้ผลดีกว่า ANN ในทุกกรณีที่ทดสอบ (4/4)** ซึ่งสอดคล้องกับลักษณะข้อมูล —
ANN ต้องการจำนวนตัวอย่างมากกว่าในการเรียนรู้ ขณะที่ SVM แบบ RBF kernel
เหมาะกับข้อมูลขนาดกลางที่มีสัญญาณรบกวนสูงมากกว่า

**นี่คือคำตอบของวัตถุประสงค์หลักตามหัวข้อ 3.3 ซึ่งบรรลุแล้ว**

## 8. ข้อเสนอเพื่อขอคำปรึกษาจากอาจารย์ที่ปรึกษา

ตามที่หัวข้อ 3.5.1 ของเอกสารโครงการกำหนดให้ประเมินผลด้วย Confusion Matrix ผ่านตัวชี้วัด
4 ตัว (Accuracy, Precision, Recall, F1-Score) ผู้วิจัยขอเสนอแนวทางการรายงานผล ดังนี้

**ทางเลือกที่ 1 — รายงานเป็น baseline lift ควบคู่กับ 4 ตัวชี้วัดตามที่กำหนดไว้**
รายงาน BUY 68.5% เทียบ baseline 58.4% (ดีกว่า 10.1 จุด) พร้อม ROC-AUC 0.715
พร้อมอธิบายหลักการ **accuracy paradox** (accuracy ไม่ใช่ตัวชี้วัดที่เหมาะสมเมื่อ class
ไม่สมดุล เพราะโมเดลที่ทายกลุ่มใหญ่เสมอก็ได้ accuracy สูงโดยไม่มีประโยชน์จริง)

**ทางเลือกที่ 2 — เพิ่มการรายงานแบบ Selective Classification**
รายงานเป็นคู่ coverage–accuracy ที่ระดับที่กำหนดไว้ล่วงหน้า ซึ่งจะแสดงตัวเลข
ระดับ 80% ได้อย่างซื่อสัตย์ และสอดคล้องกับนิยาม "ระบบสนับสนุนการตัดสินใจ"

**ทางเลือกที่ 3 — ดำเนินการเพิ่มเติมก่อนสรุป**
ทดลอง hierarchical classification, confident learning และ ordinal treatment
เพื่อให้สามารถระบุได้เต็มปากว่าตรวจสอบครบทุกแนวทางแล้ว (คาดหวังผล +2 ถึง +5 จุด)

**ทางเลือกที่ 4 — หากยืนยันเป้า 80% แบบ full-sample**
จำเป็นต้องออกแบบแบบสอบถามใหม่ทั้งฉบับ (multi-item battery ต่อ construct เพื่อรองรับ
PLS-SEM/IRT) และเก็บข้อมูลรอบใหม่ ซึ่งอยู่นอกกรอบเวลาที่เหลือของโครงการ

## 8.5 ข้อสังเกตเชิงระเบียบวิธี — กับดักการประเมินผลที่ตรวจพบระหว่างการวิจัย

*(หัวข้อนี้เสนอให้เขียนลงในบทที่ 4 หรือภาคผนวก เพราะแสดงความรัดกุมของกระบวนการตรวจสอบ)*

ระหว่างการทดลอง Confident Learning (Northcutt et al., 2021) ผู้วิจัยพบว่า
**วิธีการที่ถูกต้อง หากประเมินผลผิดวิธี จะให้ตัวเลขที่สูงเกินจริงอย่างมีนัยสำคัญ**

### การประเมินที่ผิด

คัดตัวอย่างที่อัลกอริทึมระบุว่าน่าสงสัยว่า label ผิดออกจาก **ชุดข้อมูลทั้งหมด**
แล้ววัด accuracy ใหม่ ได้ผล **0.6850 → 0.8673** (สูงขึ้น 18.2 จุด)

ตัวเลขนี้ดูน่าพอใจ แต่เมื่อตรวจสอบรายละเอียดพบว่า:

| | จำนวนตัวอย่าง | จำนวนที่ทำนายผิด |
|---|---|---|
| ก่อนคัด | 500 | ≈ 158 |
| หลังคัด | 404 | ≈ 54 |

**คัดออก 96 ตัวอย่าง แต่จำนวนที่ทำนายผิดลดลงถึง ≈ 104 ตัวอย่าง**
แสดงว่าตัวอย่างที่ถูกคัดออกเกือบทั้งหมดคือตัวอย่างที่โมเดลทำนายผิด

สาเหตุ: อัลกอริทึมใช้**ค่าความน่าจะเป็นจากโมเดลตัวเดียวกัน**เป็นเกณฑ์ระบุตัวอย่างที่น่าสงสัย
จึงไปชี้ตัวอย่างที่โมเดลทำนายไม่ถูกโดยตรง เมื่อคัดออกจากชุดทดสอบด้วย
จึงเป็นการ**ประเมินแบบวนซ้ำ (circular evaluation)** เทียบได้กับการนำข้อสอบข้อที่ทำไม่ได้
ออกก่อนคิดคะแนน

### การประเมินที่ถูกต้อง

คัดตัวอย่างที่น่าสงสัยเฉพาะใน **ชุดฝึก (train)** เท่านั้น แล้ววัดผลบน **ชุดทดสอบ (test)
ที่ไม่ถูกแตะต้อง**

| | Accuracy | Lift |
|---|---|---|
| ไม่คัด | 0.6850 | +0.1010 |
| คัด label ที่น่าสงสัยในชุดฝึก | 0.6805 | +0.0965 |

ส่วนต่าง −0.0045, paired t-test **p = 0.4627 → ไม่มีนัยสำคัญทางสถิติ**

### หลักการที่ได้

การคัดตัวอย่างออกจากชุดข้อมูลจะถูกต้องก็ต่อเมื่อ **เกณฑ์การคัดเป็นอิสระจากผลการทำนายของโมเดล**

| ประเภทการคัด | ความถูกต้อง | ผลที่ได้ |
|---|---|---|
| ใช้เกณฑ์อิสระ (attention check, straight-lining) | ✅ ถูกต้อง | ไม่เปลี่ยนแปลงผล |
| ใช้ความผิดพลาดของโมเดลเป็นเกณฑ์ | ❌ วนซ้ำ | สูงเกินจริง 18 จุด |

ผู้วิจัยจึงรายงานผลจากวิธีที่ถูกต้อง (0.6805) และเก็บโค้ดทั้งสองเวอร์ชันไว้ที่
`analysis/full_analysis.py` (เวอร์ชันผิด) และ `analysis/cl_correct.py` (เวอร์ชันถูก)
เพื่อการตรวจสอบย้อนหลัง

## 9. สรุป

วัตถุประสงค์หลักตามที่ระบุในหัวข้อ 3.3 ของเอกสารโครงการ คือ **การเปรียบเทียบ
ประสิทธิภาพของอัลกอริทึม SVM กับ ANN** ซึ่งโครงการนี้**ดำเนินการสำเร็จแล้ว
และทำเกินขอบเขตที่กำหนด** โดยเปรียบเทียบถึง 5 อัลกอริทึม พร้อมการผสมโมเดล 2 รูปแบบ

ผลที่พบว่าทุกอัลกอริทึมให้ค่าใกล้เคียงกัน **คือคำตอบของการเปรียบเทียบ ไม่ใช่ความล้มเหลว**
และการที่ไม่สามารถบรรลุ 80% ได้นั้น มีกรอบทฤษฎี (intention–behavior gap) และ
benchmark จากงานตีพิมพ์รองรับว่าเป็นคุณสมบัติของปรากฏการณ์ที่ศึกษา
มิใช่ข้อบกพร่องของระเบียบวิธีหรือของผู้วิจัย
