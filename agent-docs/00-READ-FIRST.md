## 1. สถานะปัจจุบันของโปรเจกต์

**งานปรับปรุงความแม่นยำของโมเดลปิดแล้ว** — ไม่ใช่เพราะยอมแพ้ แต่เพราะมีหลักฐานเชิงประจักษ์
12 ชิ้นที่สอดคล้องกันว่าชนเพดานสารสนเทศของข้อมูลแล้ว (ดู `รายงานเสนออาจารย์_ทบทวนวรรณกรรม_2026-08-02.md`)

**ตัวเลขที่ใช้อ้างอิงได้** (n=500, วัดจาก 20 random splits, ผ่าน nested CV แล้ว):

| โมเดล | กลุ่มตัวอย่าง | Accuracy | Baseline | Lift |
|---|---|---|---|---|
| BUY | เต็ม (500) | 0.6850 | 0.5840 | +0.1010 |
| BUY | สมดุล (416) | 0.6642 | 0.5000 | **+0.1642** |
| FUEL | เต็ม (316) | 0.4133 | 0.5316 | −0.1183 |
| FUEL | สมดุล (204) | 0.4423 | 0.3333 | **+0.1090** |

**งานที่เหลือ:** ผู้ใช้คุยกับอาจารย์ → ร่างบทที่ 4-5 → (ถ้าจะ deploy ต้องแก้ฟอร์มเว็บก่อน)

## 2. ❌ ข้อเท็จจริงที่มักเข้าใจผิด — ตรวจสอบแล้วทั้งหมด

### 2.1 "ชุดข้อมูลใหม่มีคลาสสมดุลดีขึ้น" — **ผิด กลับด้าน**

ICE = 264/500 = **52.8%** คือ**ไม่สมดุลกว่าเดิม** ชุดเก่า baseline อยู่ที่ 37.28%
ชุดใหม่พุ่งเป็น **53.16%** → นี่คือ**สาเหตุ**ที่ FUEL แพ้ baseline ไม่ใช่ข้อดี

### 2.2 "ยังไม่ได้ลอง Stacking / XGBoost / Mutual Information" — **ผิด ทำแล้วทั้งหมด**

| อ้างว่ายังไม่ทำ | ความจริง |
|---|---|
| StackingClassifier + LogisticRegression | มีอยู่แล้วที่ `train_models.py:671` ทดสอบแล้วแย่กว่าตัวเดี่ยว |
| XGBoost / HistGradientBoosting ปรับจูน | ทำแล้ว ผ่าน GridSearchCV |
| Mutual Information | ทำแล้ว + permutation test |
| Composite features | ทำแล้ว 5 ตัว ablation บอกว่าไม่ช่วย |
| SMOTE | ทำแล้ว |
| Soft-voting ensemble | ทำแล้ว |
| SVM + ANN ผสมกัน | ทำแล้ว 3 รูปแบบ **แย่ลงทุกแบบ** |

**ยังไม่เคยลองจริงมีแค่ 3 อย่าง:** `ExtraTreesClassifier`, `BorderlineSMOTE`/`SMOTETomek`,
tree-based feature importance สำหรับคัดฟีเจอร์ — ทำได้ แต่ให้ทำเป็นการทดลองใน `analysis/`
**ไม่ใช่แก้ `train_models.py`** และคาดหวังผลไม่เกิน 1-2 จุด

### 2.3 "เพิ่มข้อมูลเป็น 1,000 แล้วจะดีขึ้น" — **ผิด มีหลักฐานว่าไม่ช่วย**

Learning curve ที่รันจริง: n=100 → 67.7%, n=500 → 68.2% **แบนสนิท**
ประวัติจริง: 225 → 505 → 715 → 500 ตัวเลขไม่เคยขยับเกินค่าความผันผวน

## 3. 🚫 ข้อห้ามเด็ดขาด (เคยพลาดมาแล้วจริง)

### 3.1 ห้ามคัดตัวอย่างออกโดยใช้ความผิดพลาดของโมเดลเป็นเกณฑ์

**เคยได้ 86.7% ด้วยวิธีนี้ และมันเป็นตัวเลขปลอม**

Confident Learning ที่คัดตัวอย่างต้องสงสัยออกจาก *ทั้งชุด* แล้ววัดใหม่ → 68.5% เป็น 86.7%
แต่เมื่อดูเลข: คัดออก 96 คน แต่ **คนที่ทายผิดหายไป ~104 คน** = คนที่ถูกคัดคือคนที่โมเดลทายผิดแทบทั้งหมด
เท่ากับ **ตัดข้อที่ทำไม่ได้ออกจากข้อสอบแล้วค่อยคิดคะแนน**

ทำถูกวิธี (คัดเฉพาะใน train วัดบน test ที่ไม่แตะ) → **68.05% เทียบ 68.50%, p=0.46 ไม่มีผล**

✅ การคัดที่ทำได้: ใช้**เกณฑ์อิสระจากโมเดล** เช่น attention check / straight-lining
(ทำแล้ว คัด 278 คน ผลไม่เปลี่ยน)

### 3.1.1 ⚠️ unit tests ผ่าน ≠ deploy ได้ (บทเรียนจริง 2026-08-02)

Round 2 ของ Antigravity รัน tests ผ่าน 41/41 แล้ว deploy โมเดลใหม่ → **เว็บแนะนำผิดทันที**
(ผู้ใช้ที่ขับ EV อยู่ ได้รับคำแนะนำให้ซื้อ ICE ด้วยความมั่นใจ 98%)

เพราะ tests ตรวจแค่ **API contract** (คืนค่าครบ field, ไม่ crash)
**ไม่ได้ตรวจว่าคำแนะนำสมเหตุสมผล**

✅ **ก่อน deploy ทุกครั้ง ต้องรัน inference จริงผ่าน `predictor.py` หลายโปรไฟล์
แล้วเทียบกับโมเดลเดิม** — ดูตัวอย่างใน `รีวิว_ML-Optimization-Round2_2026-08-02.md` §1

### 3.2 ห้ามรัน `train_models.py` โดยไม่ถามผู้ใช้

จะทับ `models/buy_model.pkl` และ `fuel_model.pkl` ที่เว็บใช้อยู่ทันที
**`.pkl` ปัจจุบันคือชุดเก่า (n=715) ที่คืนค่าไว้โดยตั้งใจ**

### 3.3 ห้าม deploy โมเดลใหม่ก่อนแก้ฟอร์มเว็บ

โมเดลใหม่ใช้ฟีเจอร์จากคำถามใหม่ 10 ข้อ ซึ่ง `predict_buy.html` / `predict_fuel.html`
**ยังไม่มี** → ระบบจะเติมค่า default ทำให้ผลทำนายไม่ตรงกับ 68.5% ที่วัดไว้

### 3.4 ห้ามเปลี่ยนตัวแปรตาม (label) เป็นคำถาม "เจตนาซื้อ" (คอลัมน์ 44)

เหตุผล: (ก) **outcome switching** — เปลี่ยนหลังเห็นว่าผลเดิมไม่สวย
(ข) **construct leakage** — ฟีเจอร์ `attitude`/`subjective_norm`/`pbc_financial`
ตามทฤษฎี TPB ออกแบบมาอธิบาย intention อยู่แล้ว accuracy จะสูงขึ้นแบบไม่มีความหมาย

### 3.5 ห้ามใช้เกณฑ์ "รันจนกว่าตัวเลขจะขึ้น"

ทุกการทดลองต้อง **ประกาศล่วงหน้าว่าจะรายงานผลไม่ว่าดีขึ้นหรือแย่ลง**
โดยเฉพาะฟีเจอร์ที่เป็นผลรวมถ่วงน้ำหนัก (เช่น `ev_readiness_index`) ซึ่งปรับน้ำหนักจนตัวเลขสวยได้ไม่จำกัด

## 4. 📏 กฎการวัดผล (สำคัญมาก — เคยพลาดจนเกือบเขียนลงเล่ม)

1. **ต้องวัดด้วย 20 random splits เสมอ** ห้ามรายงานตัวเลขจาก split เดียว
   *(ตัวเลข 48.7% ของ FUEL ที่อ้างกันมาหลายสัปดาห์ เป็นค่าจาก split เดียว
   และเป็น **ค่าสูงสุด** ของช่วง 31.2%–48.7% — โชคดีที่จับได้ก่อนส่ง)*

2. **ห้ามเทียบ accuracy ข้ามชุดข้อมูลที่สัดส่วนคลาสต่างกัน — ต้องเทียบที่ lift**
   *(ตัวอย่าง: FUEL ชุดเก่า 40.75% ดูแย่กว่าชุดใหม่ 43.98% แต่ lift เก่า +3.5 ใหม่ −9.2)*

3. **`report_baseline_lift.py` ใช้ split เดียว** — ใช้ดูคร่าว ๆ ได้ แต่**ห้ามใช้ตัวเลขนั้นรายงาน**

4. **ถ้ารายงานผลกลุ่มสมดุล ต้องรายงานกลุ่มเต็มควบคู่เสมอ** เพราะตัดสินใจหลังเห็นผลแล้ว

## 5. 🔬 ข้อค้นพบเชิงระเบียบวิธีที่ต้องเขียนลงเล่ม

1. **Construct mismatch ของ label BUY** — คำถามที่ใช้เป็น label คือ *"ท่านมีแนวโน้มจะซื้อ
   รถยนต์**ตามประเภทเชื้อเพลิงที่ท่านสนใจ**หรือไม่"* ซึ่งวัด *conditional purchase*
   ไม่ใช่ *purchase intention* → อธิบายได้ว่าทำไมตัวแปรเจตนาซื้อไม่สัมพันธ์กับ label (p=0.207)
   และทำไมจุดชาร์จสัมพันธ์กับ BUY (p=0.0001) แต่ไม่สัมพันธ์กับ FUEL (p=0.950)

2. **สัดส่วนคลาสกลบผลของ FUEL** — บนกลุ่มสมดุล lift เปลี่ยนจาก −11.8 เป็น **+10.9 จุด**

3. **ข้อบกพร่องแบบสอบถาม** — โน้ต `[ข้อนี้เป็น reverse-worded...]` หลุดไปให้ผู้ตอบเห็น
   ทำให้ attention check ใช้ไม่ได้ (correlation +0.049 ทั้งที่ควรเป็นลบ)

4. **กับดัก circular evaluation ของ Confident Learning** (ดูข้อ 3.1)
   → เขียนเป็นข้อสังเกตเชิงระเบียบวิธีได้ แสดงว่ารู้ทันกับดัก

5. **Intention–Behavior Gap** (Sheeran 2002, meta-analysis 422 การศึกษา: เจตนาอธิบาย
   พฤติกรรมจริงได้ 28%) = กรอบทฤษฎีที่อธิบายเพดาน
