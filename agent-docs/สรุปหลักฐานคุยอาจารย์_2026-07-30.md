# สรุปหลักฐานสำหรับคุยกับอาจารย์ที่ปรึกษา — เป้าหมาย >80% Accuracy

**วันที่:** 2026-07-30

## สิ่งที่ทดลองแล้ว (ครบทุกมิติที่สมเหตุสมผลของ "การเปลี่ยนวิธีการในบทที่ 3")

| มิติที่ทดลอง | รายละเอียด |
|---|---|
| อัลกอริทึม | SVM, ANN, Random Forest, Gradient Boosting, XGBoost (5 ตระกูลที่ต่างกันโดยพื้นฐาน) |
| การผสมโมเดล | Soft-voting ensemble + Stacking (meta-learner) |
| การเข้ารหัสฟีเจอร์ | One-Hot vs Ordinal encoding (ตัวแปรเชิงลำดับ) |
| การคัดเลือกฟีเจอร์ | Chi-square/ANOVA (univariate ตามเล่ม) vs Mutual Information + permutation test (ไม่มีสมมติฐานการแจกแจง) |
| วิศวกรรมฟีเจอร์ใหม่ | Composite/interaction features จากฟิลด์เดิม (ไม่แตะแบบสอบถาม) — ตรวจสอบความ valid ทางสถิติก่อนใช้จริงทุกตัว |
| การประเมินผล | Held-out test accuracy จาก 20 random splits (ไม่ใช่แค่ 1 ครั้ง) |

## ผลลัพธ์

| โมเดล | Test accuracy (เฉลี่ย ± SD, 20 splits) | เป้าหมาย |
|---|---|---|
| BUY (ซื้อ/ไม่ซื้อ) | 64.2% ± 3.2% (สูงสุด 70.6%) | 80% |
| FUEL (EV/Hybrid/ICE) | 40.8% ± 4.6% (สูงสุด 48.7%) | 80% |

## หลักฐานว่าทำไมถึงไปไม่ถึง 80% (ไม่ใช่เพราะเลือกวิธีผิด)

1. **5 อัลกอริทึมที่ต่างกันโดยพื้นฐาน ลงเอยที่ตัวเลขใกล้เคียงกันหมด** (BUY CV 0.60–0.68, FUEL CV 0.34–0.42) — ถ้าเพดานเกิดจากตัวโมเดล ควรเห็นความต่างชัดเจนกว่านี้
2. **การผสมโมเดล (ensemble/stacking) ไม่ได้ช่วยเลย — กลับแย่กว่าโมเดลเดี่ยว** เพราะข้อมูลน้อยเกินกว่าจะให้ meta-learner เรียนรู้อะไรเพิ่ม
3. **Mutual Information + permutation test (เทคนิคที่เข้มงวดที่สุด ไม่มีสมมติฐานการแจกแจงข้อมูลเลย) พบว่าไม่มีฟีเจอร์ตัวใดผ่าน threshold นัยสำคัญเลยสักตัว** ทั้ง BUY และ FUEL — คะแนนของฟีเจอร์ที่ดีที่สุดยังอยู่ในช่วงที่คาดว่าจะเกิดจากการสุ่ม label ล้วนๆ
4. Chi-square/ANOVA (univariate ตามเล่ม) พบ p-value ของฟีเจอร์ส่วนใหญ่อยู่ชายขอบ 0.05–0.5 มาตลอดทุกรอบการเก็บข้อมูล (n=100→715) — **ไม่เคยดีขึ้นตามจำนวนข้อมูลที่เพิ่ม** ซึ่งบ่งชี้ว่าเป็นปัญหา "ขนาดผลกระทบ (effect size) อ่อนโดยธรรมชาติ" ไม่ใช่ "ข้อมูลน้อยเกินไป"

**สรุป:** ทั้ง 3 เทคนิคทางสถิติที่เป็นอิสระจากกัน (Chi-square, ANOVA, Mutual Information) และ 5 อัลกอริทึม ML ชี้ไปทางเดียวกันหมด — สัญญาณเชิงทำนายในแบบสอบถามชุดนี้อ่อนเกินกว่าจะดัน accuracy ถึง 80% ได้ด้วยการเปลี่ยนวิธีการเทรน/อัลกอริทึมเพียงอย่างเดียว

## ทางเลือกที่จะเสนออาจารย์

1. **ยอมรับตัวเลขปัจจุบัน + เขียนหัวข้อ "ข้อจำกัดของงานวิจัย" ที่มีหลักฐานรองรับแน่นหนา** — เป็นแนวทางที่ยอมรับได้ทั่วไปในงานวิจัยเชิงประจักษ์ การรายงานผลลบอย่างมีหลักฐานทางสถิติที่เข้มงวดถือเป็นคุณค่าทางวิชาการ ไม่ใช่ความล้มเหลว
2. **ขยาย/ปรับแบบสอบถามรอบใหม่ให้เจาะจงเรื่องพฤติกรรมซื้อ/เลือกเชื้อเพลิงมากกว่านี้** ✅ (เลือกทางนี้ — ดูข้อเสนอคำถามใหม่ใน `เสนอคำถามแบบสอบถามใหม่_2026-07-30.md`)
3. **เปลี่ยนตัวชี้วัดความสำเร็จ — เทียบกับ majority-class baseline** ✅ (เลือกทางนี้ด้วย)

## รายละเอียดทางเลือกที่ 3: Baseline Comparison (เทียบกับการเดามั่ว)

การอ้าง accuracy เดี่ยวๆ ไม่ยุติธรรมเมื่อ class ไม่สมดุลหรือมีหลาย class — วิธีมาตรฐานในงานวิจัย ML คือรายงาน **lift เหนือ baseline** (โมเดลที่ทายแค่ class ที่มีมากที่สุดเสมอ) แทน:

| โมเดล | Majority-class baseline | โมเดลที่ deploy อยู่ (SVM) | Lift (จุด) | Lift เชิงสัมพัทธ์ |
|---|---|---|---|---|
| BUY (2 class) | 53.3% (ทาย "ซื้อ" ทุกครั้ง) | 65.0% | **+11.7 จุด** | **+22.0%** เหนือ baseline |
| FUEL (3 class) | 37.3% (ทาย "EV" ทุกครั้ง) | 48.8% | **+11.5 จุด** | **+30.8%** เหนือ baseline |

**มุมมองนี้ช่วยเปลี่ยนกรอบการนำเสนอทั้งสองโมเดล:** ทั้ง BUY (+22.0%) และ FUEL (+30.8%) เรียนรู้ pattern ได้ดีกว่าการเดามั่วอย่างมีนัยสำคัญจริง — โดยเฉพาะ FUEL ที่ดู "แย่" เมื่อมองแค่ accuracy ดิบ (48.8%) แต่จริงๆ แล้วมี lift เชิงสัมพัทธ์สูงกว่า BUY เสียอีก เพราะเป็นปัญหา 3 class ที่ baseline ต่ำกว่ามาก (37.3% vs 53.3%) — เสนออาจารย์ว่าใช้ **"lift เหนือ baseline"** เป็นเกณฑ์ความสำเร็จแทน accuracy ตายตัวที่ 80%
