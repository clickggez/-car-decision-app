==================================================
สรุป: ไม่มีปัญหาค้างแล้ว — ปิดงาน ML ของวันนี้
==================================================
ทั้ง BUY และ FUEL model อยู่ในสถานะดีที่สุดเท่าที่เคยเทรนมาในโปรเจกต์นี้
และได้ทดลองหาทางปรับปรุงจนครบทุกช่องทางที่ทำได้แล้วภายในขอบเขตงานวันนี้
(ไม่แก้ signature, ไม่เก็บข้อมูลเพิ่ม)

==================================================
predict_buy — 65.0% (พร้อมใช้งาน ไม่มีปัญหา)
==================================================
precision/recall สมดุลทั้งสอง class (0.68/0.64 และ 0.62/0.66)
เพดานความแม่นยำจริงน่าจะอยู่ราว 65-70% ด้วยชุดคำถามปัจจุบัน (feature
selection ยังไม่เคยมี field ไหนผ่าน p<0.01 ชัดเจน) — ถือว่าอยู่ที่เพดาน
แล้ว ไม่ต้องทำอะไรเพิ่ม

==================================================
predict_fuel — 48.7% (เพดานจริง ยืนยันด้วยการทดลอง 5 แนวทาง)
==================================================
ทดลองครบแล้ว:
1. เพิ่มข้อมูล (ICE 65->82->105 ตัวอย่าง) — ไม่ช่วย จำนวน field ที่ผ่าน
   เกณฑ์ไม่ขยับ
2. ผ่อนปรน alpha (0.10->0.15) + บังคับเก็บ prev_car — ได้ผล! 32.5%->48.7%
3. force_keep เพิ่ม usage_type + distance — แย่ลง (36.2%) ย้อนกลับแล้ว
4. เพิ่มฟีเจอร์ใหม่ priority_count (ไม่บังคับเก็บ) — ไม่ผ่านเกณฑ์ ถูก
   ตัดทิ้งเอง ผลเหมือนเดิม (48.7%)
5. (ก่อนหน้านั้น) แก้บั๊ก GridSearchCV scoring — จำเป็นสำหรับ BUY ไม่ใช่
   FUEL แต่เป็นส่วนหนึ่งของ pipeline เดียวกัน

**เหลือแค่ 2 ทางที่ไม่ได้ทำ เพราะนอกขอบเขตงานวันนี้:**
- แก้ signature ของ predict_fuel() ให้รับฟีเจอร์เพิ่ม (เช่น budget/income
  เหมือน BUY) — ต้องขออนุญาตชัดเจนก่อนตามกฎ .cursorrules
- ออกแบบคำถามแบบสอบถามใหม่ที่เจาะจงเรื่องเชื้อเพลิงโดยตรง แล้วเก็บข้อมูล
  รอบใหม่ — เป็นงานออกแบบวิจัยคนละ scope จาก retrain

ถ้าจะทำต่อในอนาคต ให้เริ่มจาก 2 ทางนี้ ไม่ใช่ลองปรับ alpha/feature
selection เพิ่มอีก (ทดสอบจนอิ่มตัวแล้ว)
