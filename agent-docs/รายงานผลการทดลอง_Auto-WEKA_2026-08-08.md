# รายงานผลการทดลองด้วย Auto-WEKA
## การค้นหาแบบจำลองอัตโนมัติทั่วทั้งปริภูมิอัลกอริทึม เพื่อตรวจสอบเพดานความแม่นยำ

**โครงการ:** ระบบสนับสนุนการตัดสินใจเลือกซื้อรถยนต์ โดยใช้หลักการทำเหมืองข้อมูล (CarDSS)
**วันที่:** 8 สิงหาคม 2569
**ที่มา:** อาจารย์ที่ปรึกษาแนะนำให้ทดลองใช้เครื่องมือใน WEKA เพื่อดูว่าความแม่นยำจะสูงขึ้นได้หรือไม่
**วัตถุประสงค์ของรายงาน:** รายงานผลการทดลองตามข้อเสนอแนะของอาจารย์อย่างครบถ้วน ทั้งผลที่ดีขึ้นและแย่ลง

---

## บทสรุปสำหรับผู้บริหาร

1. **ดำเนินการตามข้อเสนอแนะครบถ้วนแล้ว** — รัน Auto-WEKA บนชุดข้อมูลทั้ง 4 ชุด รวมเวลาประมวลผล
   4 ชั่วโมง โดยให้ระบบค้นหาอัตโนมัติทั่วทั้งปริภูมิ (ทุกอัลกอริทึม × ทุกไฮเปอร์พารามิเตอร์ ×
   ทุกวิธีคัดเลือกฟีเจอร์) โดยไม่มีการกำหนดทิศทางจากผู้วิจัย

2. **predict_buy ได้ 71.20%** เทียบกับ 68.50% ที่ปรับแต่งด้วยมือไว้เดิม ส่วนต่าง 2.70 จุด
   **อยู่ในช่วงความผันผวนของการวัด ไม่ถือว่าแตกต่างอย่างมีนัยสำคัญ**

3. **Auto-WEKA เลือกอัลกอริทึม SVM (SMO) เช่นเดียวกับที่ใช้อยู่เดิม** — เป็นการยืนยันโดยอิสระว่า
   การเลือกแบบจำลองของผู้วิจัยเหมาะสมกับข้อมูลชุดนี้แล้ว

4. **predict_fuel มีตัวเลขความแม่นยำสูงขึ้น แต่คุณภาพแบบจำลองแย่ลง** — ค่า Kappa เท่ากับ
   −0.0059 (เทียบเท่าการเดาสุ่ม) เนื่องจากแบบจำลองเรียนรู้ที่จะทำนายคลาสใหญ่ที่สุดเพียงคลาสเดียว
   รายละเอียดในหัวข้อ 4.2 **เป็นกรณีศึกษาที่ชี้ว่าเหตุใดจึงต้องรายงาน Kappa ควบคู่กับ accuracy เสมอ**

5. **ข้อสรุปโดยรวม:** ผลการทดลองนี้เป็นหลักฐานเชิงประจักษ์ชิ้นที่ 13 ที่สอดคล้องกับข้อสรุปเดิมว่า
   ความแม่นยำถูกจำกัดด้วยสารสนเทศในชุดข้อมูล มิใช่ด้วยการเลือกแบบจำลองหรือวิธีการปรับแต่ง
   และเป็นหลักฐานที่มีน้ำหนักที่สุดในบรรดาทั้งหมด เพราะปราศจากอคติในการเลือกของผู้วิจัย

## 1. เหตุผลเชิงระเบียบวิธีที่การทดลองนี้มีคุณค่า

หลักฐานเดิม 12 ชิ้น (ดู `รายงานเสนออาจารย์_ทบทวนวรรณกรรม_2026-08-02.md`) มีลักษณะร่วมกันคือ
**ผู้วิจัยเป็นผู้เลือกเองว่าจะทดลองอะไร** ซึ่งเปิดช่องให้ตั้งข้อสงสัยได้ว่าอาจมีวิธีที่ยังไม่ได้ลอง

Auto-WEKA ปิดช่องว่างนี้ เพราะใช้ SMAC (Sequential Model-based Algorithm Configuration ซึ่งเป็น
Bayesian optimization) ค้นหาโดยอัตโนมัติครอบคลุม:

- อัลกอริทึมจำแนกประเภททั้งหมดที่มีใน WEKA (ต้นไม้ตัดสินใจ, SVM, โครงข่ายประสาทเทียม,
  Bayesian, lazy learner, rule-based, meta-classifier/ensemble ทุกชนิด)
- ไฮเปอร์พารามิเตอร์ของแต่ละอัลกอริทึม (พื้นที่ค้นหารวมนิยามไว้ในไฟล์ `autoweka.params` ขนาด 49 KB)
- วิธีคัดเลือกฟีเจอร์ (CfsSubsetEval, BestFirst, GreedyStepwise ฯลฯ) ผสมกับอัลกอริทึมทุกแบบ

**ข้อสรุปที่ได้จึงไม่ขึ้นกับความรู้หรือความลำเอียงของผู้วิจัย**

## 2. วิธีดำเนินการ

### 2.1 การเตรียมข้อมูล

แปลงข้อมูลแบบสอบถามเป็นรูปแบบ ARFF ด้วยสคริปต์ `analysis/export_arff.py` ซึ่ง**เรียกใช้ฟังก์ชัน
เตรียมข้อมูลชุดเดียวกับที่ใช้เทรนแบบจำลองจริง** (`build_buy` / `build_fuel` จาก `analysis/ablation.py`
ซึ่งใช้ตรรกะเดียวกับ `car-dss/train_models.py`) เพื่อให้ตัวเลขเปรียบเทียบกันได้โดยตรง

**การตรวจสอบความถูกต้อง:** ค่า baseline (ZeroR) ที่ WEKA คำนวณได้ตรงกับค่าที่รายงานไว้เดิมทุกชุด
(58.40% / 50.00% / 53.16% / 33.33%) ยืนยันว่าเป็นข้อมูลชุดเดียวกัน

**สิ่งที่จงใจไม่ทำในไฟล์ ARFF:** ไม่ทำ one-hot encoding, ไม่ทำ scaling, ไม่ทำ SMOTE,
ไม่คัดเลือกฟีเจอร์ล่วงหน้า — เพื่อให้ Auto-WEKA ค้นหา pipeline ได้เต็มพื้นที่ หากประมวลผล
ล่วงหน้าไปก่อนจะเป็นการจำกัดทางเลือกโดยไม่ตั้งใจ

### 2.2 ชุดข้อมูลที่ใช้

| ไฟล์ | ตัวอย่าง | ฟีเจอร์ | baseline |
|---|---|---|---|
| `cardss_buy.arff` | 500 | 27 | 58.40% |
| `cardss_buy_balanced.arff` | 416 | 27 | 50.00% |
| `cardss_fuel.arff` | 316 | 26 | 53.16% |
| `cardss_fuel_balanced.arff` | 204 | 26 | 33.33% |

ชุด "สมดุล" ได้จากการสุ่มลดจำนวนคลาสที่มากเกินให้เท่ากับคลาสที่น้อยที่สุด (random undersampling)
ตามเหตุผลที่บันทึกไว้ใน `analysis/balanced_subsample.py` คือกลุ่มตัวอย่างรอบนี้เก็บ ICE เพิ่ม
โดยตั้งใจจนเป็น 52.8% ทำให้ไม่ได้เป็นตัวแทนสัดส่วนประชากรอยู่แล้ว

### 2.3 ค่าที่ใช้ในการค้นหา

| พารามิเตอร์ | ค่า |
|---|---|
| `timeLimit` | 25 นาที ต่อการเทรน 1 ครั้ง |
| `memLimit` | 1536 MB ต่อ SMAC worker |
| `parallelRuns` | 2 (ค้นหาขนาน 2 สาย เลือกผลที่ดีที่สุด) |
| `metric` | errorRate |
| การประเมิน | 10-fold stratified cross-validation |
| เวลาประมวลผลจริง | 00:23 – 04:22 น. รวม 3 ชั่วโมง 59 นาที (รันทั้ง 4 ชุดพร้อมกัน) |

หมายเหตุ: 10-fold cross-validation ทำให้ต้องเทรนแบบจำลอง 11 ครั้ง (10 fold + 1 ครั้งบนข้อมูลเต็ม)
งบประมาณการค้นหารวมต่อชุดข้อมูลจึงเท่ากับ 25 × 11 = 275 นาที

### 2.4 ข้อจำกัดทางเทคนิคที่พบและวิธีแก้

Auto-WEKA ไม่สามารถทำงานบน WEKA 3.8.7 ที่ติดตั้งมาตรฐานได้ เนื่องจากตัวติดตั้งแถม Java 25 มาด้วย
แต่ SMAC ซึ่งเป็นตัวค้นหาเรียกใช้ `System.setSecurityManager()` ซึ่ง**Java ตัดทิ้งถาวรตั้งแต่
เวอร์ชัน 24 (JEP 486)** ทำให้กระบวนการค้นหาหยุดทำงานทันทีที่เริ่ม แล้วรายงานเป็นข้อผิดพลาด
`NullPointerException` ที่ไม่สื่อถึงสาเหตุที่แท้จริง

**วิธีแก้:** ให้ WEKA ทำงานบน Java 8 (ไฟล์ `WEKA (Java 8).bat`) เป็นข้อจำกัดของตัวเครื่องมือ
ไม่เกี่ยวข้องกับข้อมูลหรือระเบียบวิธีวิจัย

## 3. ผลการทดลอง

### 3.1 ความแม่นยำ (10-fold cross-validation)

| ชุดข้อมูล | Auto-WEKA | baseline | lift | ผลเดิม (20 splits) | lift เดิม |
|---|---|---|---|---|---|
| BUY เต็ม (500) | **71.20%** | 58.40% | +12.80 | 68.50% | +10.10 |
| BUY สมดุล (416) | 66.11% | 50.00% | +16.11 | 66.42% | +16.42 |
| FUEL เต็ม (316) | 52.53% | 53.16% | −0.63 | 41.33% | −11.83 |
| FUEL สมดุล (204) | 29.41% | 33.33% | −3.92 | 44.23% | +10.90 |

### 3.2 แบบจำลองที่ Auto-WEKA เลือกเอง

| ชุดข้อมูล | แบบจำลอง | Kappa |
|---|---|---|
| BUY เต็ม | **SMO (SVM)** + NormalizedPolyKernel, C=1.0295, E=0.2822 | 0.3834 |
| BUY สมดุล | Bagging + Logistic (P=26, I=17) | 0.3221 |
| FUEL เต็ม | LWL + DecisionTable + CfsSubsetEval/BestFirst | −0.0059 |
| FUEL สมดุล | JRip (N=2.578, O=4) | −0.0588 |

## 4. การตีความผล

### 4.1 predict_buy — ส่วนต่างอยู่ในช่วงความผันผวน

ตัวเลข 71.20% เทียบกับ 68.50% **ไม่สามารถนำมาเทียบกันโดยตรงได้** เพราะใช้วิธีประเมินต่างกัน
(Auto-WEKA ใช้ 10-fold cross-validation ครั้งเดียว ส่วนผลเดิมใช้ค่าเฉลี่ยจาก 20 random splits
ซึ่งมีส่วนเบี่ยงเบนมาตรฐาน ±3.5 จุด) ส่วนต่าง 2.70 จุดจึงอยู่ภายในช่วงความผันผวนปกติ

**การเปรียบเทียบที่ยุติธรรมคือเทียบภายในโปรโตคอลเดียวกันของ WEKA เอง:**

| วิธี | accuracy (10-fold CV) |
|---|---|
| SMO ค่าเริ่มต้น ไม่ปรับแต่งใด ๆ | 70.00% |
| Auto-WEKA ค้นหาอัตโนมัติ 4 ชั่วโมง | 71.20% |
| **ส่วนต่าง** | **+1.20 จุด** |

การค้นหาทั่วทั้งปริภูมิอัลกอริทึมเป็นเวลา 4 ชั่วโมง ให้ผลดีกว่าการใช้ค่าเริ่มต้นโดยไม่ปรับแต่งเลย
เพียง 1.20 จุด **และแบบจำลองที่ค้นเจอคือ SVM ซึ่งเป็นอัลกอริทึมเดียวกับที่ผู้วิจัยเลือกใช้อยู่แล้ว**

### 4.2 predict_fuel — ตัวเลขสูงขึ้นแต่แบบจำลองไร้ความสามารถ

ความแม่นยำของ FUEL เต็มสูงขึ้นจาก 41.33% เป็น 52.53% ซึ่ง**เมื่อดูเฉพาะ accuracy จะเข้าใจผิดว่าดีขึ้น**
แต่ confusion matrix เปิดเผยความจริง:

```
   a   b   c   <-- ทำนายว่า
   0   0  68 |  a = EV      → ทำนาย EV ถูก 0 จาก 68 ราย
   0   1  79 |  b = Hybrid  → ทำนาย Hybrid ถูก 1 จาก 80 ราย
   0   3 165 |  c = ICE
```

แบบจำลองทำนายว่า "ICE" ให้กับผู้ตอบ 312 รายจาก 316 ราย กล่าวคือ**เรียนรู้ที่จะทำนายคลาสที่พบมาก
ที่สุดเพียงคลาสเดียว** ค่า Kappa = −0.0059 ยืนยันว่าไม่มีความสามารถในการจำแนกเหนือกว่าการเดาสุ่ม

**ในเชิงการใช้งานจริง แบบจำลองนี้ใช้ไม่ได้เลย** เพราะระบบสนับสนุนการตัดสินใจที่ไม่มีวันแนะนำ
รถยนต์ไฟฟ้าหรือไฮบริดให้ผู้ใช้รายใดเลย ย่อมไม่บรรลุวัตถุประสงค์ของงานวิจัย

> **ข้อสังเกตเชิงระเบียบวิธี:** กรณีนี้เป็นตัวอย่างชัดเจนว่าเหตุใดจึงต้องรายงาน Kappa และ macro F1
> ควบคู่กับ accuracy เสมอ หากรายงานเฉพาะ accuracy จะสรุปผิดว่า Auto-WEKA ปรับปรุง predict_fuel
> ได้ถึง 11 จุด ทั้งที่ความจริงคือแบบจำลองเสื่อมลงจนไร้ประโยชน์

### 4.3 predict_fuel ชุดสมดุล — ต่ำกว่าการเดาสุ่ม

ความแม่นยำ 29.41% ต่ำกว่าเกณฑ์การเดาสุ่มที่ 33.33% และ Kappa = −0.0588 โดย confusion matrix
กระจายเกือบเท่ากันทุกช่อง แสดงว่า**เมื่อขจัดผลของความไม่สมดุลของคลาสออกไปแล้ว Auto-WEKA
ค้นหาเป็นเวลา 4 ชั่วโมงก็ยังไม่พบสัญญาณใด ๆ ในข้อมูลชุด FUEL**

ผลนี้สอดคล้องกับข้อสรุปเดิมว่าฟีเจอร์ที่มีอยู่ไม่เพียงพอต่อการทำนายประเภทเชื้อเพลิง

## 5. ข้อจำกัดของการทดลองนี้

รายงานไว้เพื่อความโปร่งใสตามระเบียบวิธี:

1. **วิธีประเมินไม่ตรงกับผลเดิม** — Auto-WEKA ใช้ 10-fold cross-validation ครั้งเดียว
   ส่วนผลเดิมใช้ค่าเฉลี่ยจาก 20 random splits จึงเทียบตัวเลขตรง ๆ ไม่ได้ (แก้ไขโดยใช้การเปรียบเทียบ
   ภายในโปรโตคอลเดียวกันในหัวข้อ 4.1 แทน)

2. **ชุดข้อมูลสมดุลใช้ seed เดียว** — ไฟล์ ARFF เป็นชุดข้อมูลตายตัวจึงต้องเลือก seed เดียว (seed=42)
   ต่างจาก `balanced_subsample.py` ที่ทำซ้ำ 10 seed แล้วเฉลี่ย ตัวเลขจึงอาจต่างจากรายงานเดิมเล็กน้อย

3. **งบประมาณการค้นหาจำกัดที่ 25 นาทีต่อการเทรน** — หากเพิ่มเวลาอาจได้ผลดีขึ้นเล็กน้อย
   แต่จากเส้นแนวโน้มของ SMAC ในบันทึกการทำงาน ค่าประมาณคุณภาพเริ่มคงที่ก่อนหมดเวลาแล้ว

4. **รายงานผลครบทุกชุดโดยไม่คัดเลือก** — รวมถึงชุด FUEL สมดุลที่ให้ผลแย่กว่าเดิมมาก
   ตามหลักการที่บันทึกไว้ใน `analysis/README.md` ว่าห้ามเลือกรายงานเฉพาะแบบที่ตัวเลขดีกว่า

## 6. ข้อสรุป

การทดลองด้วย Auto-WEKA ซึ่งค้นหาแบบจำลองอัตโนมัติทั่วทั้งปริภูมิอัลกอริทึมเป็นเวลา 4 ชั่วโมง
ให้ความแม่นยำ 71.20% สำหรับ predict_buy ซึ่งไม่แตกต่างอย่างมีนัยสำคัญจาก 68.50% ที่ได้จาก
การปรับแต่งด้วยมือ และเลือกอัลกอริทึม SVM เช่นเดียวกัน ส่วน predict_fuel นั้นแม้ตัวเลขความแม่นยำ
จะสูงขึ้น แต่ค่า Kappa ที่เท่ากับศูนย์ชี้ว่าแบบจำลองเพียงทำนายคลาสที่พบมากที่สุดเท่านั้น

ผลทั้งหมดยืนยันว่า **ความแม่นยำของระบบถูกจำกัดด้วยสารสนเทศที่มีอยู่ในชุดข้อมูล มิใช่ด้วยการเลือก
แบบจำลองหรือวิธีการปรับแต่ง** และการยืนยันนี้มีน้ำหนักเป็นพิเศษเพราะได้จากเครื่องมืออิสระที่ค้นหา
โดยปราศจากอคติของผู้วิจัย

## 7. คำถาม–คำตอบที่คาดว่าจะถูกถาม

**ถาม: ทดลองใช้ Auto-WEKA ตามที่แนะนำแล้ว ผลเป็นอย่างไร**
> รันครบทั้ง 4 ชุดข้อมูล ใช้เวลาประมวลผล 4 ชั่วโมง ให้ระบบค้นหาอัตโนมัติทั่วทั้งปริภูมิอัลกอริทึม
> ผล predict_buy ได้ 71.20% เทียบกับ 68.50% เดิม ต่างกัน 2.70 จุดซึ่งอยู่ในช่วงความผันผวนของ
> การวัด และที่สำคัญคือ Auto-WEKA เลือก SVM ซึ่งเป็นอัลกอริทึมเดียวกับที่ใช้อยู่เดิม

**ถาม: Auto-WEKA คืออะไร ต่างจากการทดลองเองอย่างไร**
> เป็นส่วนขยายของ WEKA ที่ใช้ SMAC ซึ่งเป็น Bayesian optimization ค้นหาชุดค่าที่ดีที่สุดโดยอัตโนมัติ
> ครอบคลุมอัลกอริทึมทั้งหมดใน WEKA พร้อมไฮเปอร์พารามิเตอร์และวิธีคัดเลือกฟีเจอร์
> ข้อได้เปรียบคือปราศจากอคติของผู้วิจัย เพราะผู้วิจัยไม่ได้เป็นผู้กำหนดว่าจะทดลองอะไรบ้าง

**ถาม: เหตุใดความแม่นยำจึงไม่เพิ่มขึ้นอีก**
> เพราะข้อจำกัดอยู่ที่ตัวข้อมูล ไม่ใช่ที่วิธีการ ก่อนหน้านี้มีหลักฐานเชิงประจักษ์ 12 ชิ้นที่สอดคล้องกัน
> (learning curve แบน, nested CV, ablation, confident learning ฯลฯ) การทดลองนี้เป็นหลักฐาน
> ชิ้นที่ 13 และมีน้ำหนักที่สุด เพราะเป็นการค้นหาโดยเครื่องมืออิสระที่ครอบคลุมทั้งปริภูมิ

**ถาม: predict_fuel ดูดีขึ้นจาก 41% เป็น 52% ไม่ใช่หรือ**
> ตัวเลขดูดีขึ้นแต่แบบจำลองแย่ลงครับ ค่า Kappa เท่ากับ −0.0059 ซึ่งเทียบเท่าการเดาสุ่ม
> เมื่อดู confusion matrix จะพบว่าแบบจำลองทำนาย ICE ให้ 312 จาก 316 ราย และทำนาย EV
> ถูก 0 รายจาก 68 ราย ความแม่นยำที่สูงขึ้นจึงมาจากการทำนายคลาสใหญ่ที่สุดเพียงคลาสเดียว
> ซึ่งสำหรับระบบสนับสนุนการตัดสินใจถือว่าใช้งานไม่ได้ นี่คือเหตุผลที่รายงาน Kappa ควบคู่เสมอ

**ถาม: เหตุใดจึงต้องใช้ Java 8**
> Auto-WEKA ใช้ SMAC เป็นตัวค้นหา ซึ่งเรียกใช้ `System.setSecurityManager()` แต่ Java
> ตัดฟังก์ชันนี้ทิ้งถาวรตั้งแต่เวอร์ชัน 24 ตาม JEP 486 ขณะที่ WEKA 3.8.7 แถม Java 25 มาให้
> จึงต้องรันบน Java 8 เป็นข้อจำกัดทางเทคนิคของเครื่องมือ ไม่เกี่ยวกับข้อมูลหรือระเบียบวิธี

**ถาม: ทำไมไม่ให้ Auto-WEKA ค้นหานานกว่านี้**
> จากบันทึกการทำงานของ SMAC ค่าประมาณคุณภาพของแบบจำลองที่ดีที่สุดเริ่มคงที่ก่อนหมดงบเวลาแล้ว
> การเพิ่มเวลาจึงคาดว่าให้ผลเปลี่ยนแปลงไม่เกิน 1-2 จุด ซึ่งไม่กระทบข้อสรุป อย่างไรก็ตาม
> หากอาจารย์เห็นควร สามารถรันซ้ำด้วยงบเวลาที่สูงขึ้นได้ทันทีเพราะสคริปต์ทำซ้ำผลได้
